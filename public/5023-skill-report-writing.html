EpiAgentKit Skill · report-writing：专业中文报告生成与排版

EpiAgentKit
科研 Skills
论文与报告
全面介绍 report-writing 的报告体例、单源取数、表图入文、Word 排版、版本归档和与论文写作的边界。
发布于

2026年7月23日

report-writing 把已经成立的分析结果、流程、进展或操作要求转成面向读者和决策者的专业中文报告。它借鉴学术写作的证据约束，但采用报告体例：结论先行、结构灵活、面向行动，并允许使用表格和有限清单帮助读者快速执行。

报告与论文的分工

论文需要向审稿人证明研究严谨且可发表，通常使用固定的学术结构和严格引文规范；报告服务于决策者、客户、团队或执行人，开头先给结论和行动依据，再按读者需要组织背景、方法、发现、建议和附录。

两者都必须做到数字有源、零编造、术语一致和论断与证据匹配。报告可以更直接，但不能因为读者不是审稿人而降低事实标准。

适用场景

本技能覆盖分析报告、结果报告、工作报告、进展报告、说明文档、指南、手册、操作指引、备忘和纪要。正式期刊论文、学位论文与投稿材料转 academic-publishing；统计咨询的完整外发包转 consulting-delivery。

用户只要正文时，技能返回净稿，不创建文件。用户要求正式报告文件时，默认生成同名、同目录、内容一致的 Markdown 与 Word；明确只要一种格式时服从请求。

数据与结果单源

报告中的样本量、估计值、置信区间、P 值、百分比、日期和金额必须来自项目结果文件、导出表或用户明确来源。正式项目优先通过 val() 从 results.yaml 取数，源里没有的内容标记待确认，不在报告中就地补写。

数字需要修改时先回结果单源修改，再重新传播到人读摘要、表格和报告。这样可以避免同一指标在报告正文和附表中出现两个版本。

内容结构

报告类型 推荐结构
分析或结果报告 执行摘要、背景目的、方法、发现、结论建议、附录
进展或工作报告 核心要点、已完成、进行中、待办与风险、下一步
操作指南或手册 用途与对象、核心概念、分步操作、结果解读、注意事项
说明或备忘 结论先行、关键事实、影响、需要决策的事项

执行摘要放在开头，使读者在前四分之一内容中抓住主要结论。正文以完整段落为主，凡是包含因果、对比、解读或推论的内容都应写成连贯叙述。项目符号只用于真正并列的步骤、勾选项和纯枚举。

图表入文

报告涉及的数据若已有 03_tables/ 中的 Excel 表格，应读取并以三线表插入；已有 04_figures/ 中的图件，应嵌入正文而不是只写“见图”。表题放在表上方，图题放在图下方，编号按行文顺序连续。

没有现成图表时，统计数据图转 publication-figures；流程、结构、机制、概念和章节视觉转 research-visuals；需要实际电子表格时使用 xlsx。真实科研原始图像不得生成式重绘。

Word 排版

报告生成器使用 python-docx，并通过 references/build_report.py 的 Report 类统一处理字体、标题页、三线表、Excel 取数、图片、统计符号和双格式保存。

默认排版保持白底黑字，中文正文使用宋体，英文和数字使用 Times New Roman，标题使用黑体或微软雅黑。层级依靠字号、字重、间距和边框，不自动增加深色标题条、彩色表头、渐变或大面积灰底。

版式项目 默认要求
标题区 标题加粗居中，可含日期、版本或编制方，不放灰色说明小字
正文 1.5 倍行距、首行缩进 2 字符、段后适度留白
表格 三线表、无竖线、数字右对齐、白底黑字
图片 居中嵌入实际图件，图题在下方
统计符号 P、t、F、r 等按规范使用斜体

当前版与归档

报告目录只保留一组稳定语义名的当前版，不能并列保存“最终版”“完善版”“v2”等文件。重生成前，把被替代的报告、脚本、素材和核验输出按批次移入 09_backup/，登记 MANIFEST.md 和备份索引。

生成流程

  1. 明确读者、目的、范围和报告类型。
  2. 从单源提取数字，收集实际表格和图件。
  3. 按“结论先行、每节一主题”逐节写作。
  4. 把数字与解释、图表引用织入完整段落。
  5. 需要文件时使用生成器输出稳定命名的 Markdown 和 Word。
  6. 检查数字、术语、编号、字体、表图位置和当前版唯一性。

内部组成

SKILL.md 保存报告类型、写作与版式主流程；references/build_report.py 提供统一的 Word 生成器，包括 val() 单源取数、table_from_xlsx()、figure() 和 save(..., also_md=True) 等能力。

使用示例

根据 results.yaml、03_tables 和 04_figures 生成一份分析报告。开头给执行摘要，正文用完整段落解读结果，实际插入已有表图，并同时输出同名 Markdown 与 Word。
把这份流程说明改写成操作指南。只要正文，不生成文件；步骤可以使用清单，原理与注意事项写成完整段落。

与其他 Skills 的协作

academic-humanizer 负责事实保持和专业语体终审；docx 负责既有 Word 的读取、编辑、转换和底层 OOXML；publication-figures 与 research-visuals 分别提供统计图和非统计视觉；consulting-delivery 负责咨询包整体打包。

能力边界

本技能不替代论文写作，也不从未知来源补齐统计数字。只要报告正文时不会擅自创建 Word；只有在实际文件交付中才加入文件操作 skill。

安装与入口

python scripts/epiagentkit.py install --target all --preset writing --yes
