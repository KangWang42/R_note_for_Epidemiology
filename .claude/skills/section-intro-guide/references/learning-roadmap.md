# R 学习路线设计

## 用能力而不是时间分阶段

学习时间受既有编程经验、统计基础、目标任务和练习频率影响，不给“若干周熟练”一类普遍承诺。路线图以可验证能力为节点：

| 阶段 | 核心能力 | 可验证任务 | 常见前置 |
|---|---|---|---|
| 环境与对象 | 运行 R、创建对象、查看帮助和对象结构 | 从空会话运行一个脚本并解释输出 | 文件与目录基本概念 |
| 数据处理 | 导入、核对类型、筛选、变形、连接和缺失检查 | 把一个原始表变为分析表并核对行数 | 向量与数据框 |
| 可视化与描述 | 按问题选择图和描述量 | 生成一张可读图并说明其不能回答什么 | 数据类型与分组 |
| 统计或建模 | 根据研究问题选择方法、拟合、诊断和解释 | 完成一个小型分析并报告效应与不确定性 | 设计和概率基础 |
| 可复现输出 | 脚本化、项目路径、版本记录和 Quarto | 从输入重建报告或页面 | 前述工作流 |
| 专业方向 | 因果、预测、生存、卫生经济等领域方法 | 按领域规范完成一个端到端案例 | 对应设计与方法基础 |

## 路由原则

- 先根据读者的最终任务选择必需能力，再反向安排前置，不按包名堆课程。
- Base R 与 tidyverse 可以并行介绍，但同一小节保持一种主要语法，明确对象与行为是否相同。
- 统计路线先讲研究问题、数据结构和效应尺度，再讲软件调用。
- 机器学习路线把数据泄漏、重采样、基线模型、校准和外部验证放在“追求更高指标”之前。
- 每一阶段保留一个小项目和明确完成条件；教程数量、图表数量和包数量不是完成标准。
