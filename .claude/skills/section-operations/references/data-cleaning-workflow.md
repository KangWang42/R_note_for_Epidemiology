# 数据清洗教程原则

## 数据链

原始输入保持只读。先复制或派生分析数据，再记录读取参数、编码、行列数和主键检查。每次转换说明输入、规则、受影响记录数和验证结果；不能为了得到“干净数据”静默删除异常记录。

## 推荐顺序

1. 核对文件身份、编码、分隔符、列名和变量类型；
2. 检查主键唯一性、重复定义、记录时间和跨表关系；
3. 将特殊缺失码统一为显式缺失，但保留转换映射；
4. 用方案或权威来源定义范围与逻辑检查，不把 IQR、Z 分数或固定医学范围当作自动删除规则；
5. 处理单位、日期、分类水平和派生变量，并回查最早来源；
6. 输出行数变化、缺失变化、异常清单和不可解决问题；
7. 保存可复现脚本与派生数据，不覆盖原文件。

## 缺失数据

描述缺失位置、比例、模式和采集机制。完整案例、单次填补、多重插补、加权与 MNAR 敏感性依赖不同假设。不要写“MCAR 就删除”“m=5 即可”或“多重插补普遍推荐”；选择应服从分析目标、缺失机制和模型结构。

## 重复与异常

完全相同行不一定是重复个体；同一 ID 多行也可能是合法纵向记录。先定义业务主键和允许的重复，再决定保留、合并或标记。统计异常值是核验线索，不是删除许可；需要回查原始来源并评估对结果的影响。

## 验证输出

教程示例至少展示：读取后的维度、主键或重复检查、转换前后计数、逻辑异常清单、缺失概览和最终断言。任何过滤步骤都报告删除条件与数量。
