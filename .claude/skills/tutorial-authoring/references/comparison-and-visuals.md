# 易混淆内容与图件决策

## 1. 写作前建立辨析清单

在起草正文前，先判断是否存在会妨碍当前学习目标的易混淆项。只有名称、输入或输出相似，常被当作可以互换，且误选会影响后续操作或解释时，才列出最接近的 2–4 个方法、工具、图形或工作流。没有这种风险时，不增加比较章节。对确有必要的候选先回答：

1. 它们分别解决什么问题，目标量或产物是什么；
2. 需要什么数据结构、输入、版本或运行条件；
3. 核心假设、默认行为和相关性或随机性如何处理；
4. 输出应怎样解释，哪些结果不能直接互比；
5. 需要检查什么诊断、失败状态或适用边界；
6. 什么条件下优先使用，什么信号提示应改用其他方案。

若选错候选会使后续公式、代码或结果解释跑偏，把辨析放在正文前段，在第一次深入原理或调用核心函数之前完成。若差异只影响进阶用法，可放到对应步骤旁边；若不影响本文任务，只提供必要的延伸链接或完全省略。

比较用于定位问题，不做没有口径的优缺点排行。不得用“更高级”“更稳健”“更准确”“代码更短”代替适用条件，也不得根据哪个结果更显著反向选择方法。

## 2. 选择表达方式

| 需要表达的关系 | 首选形式 | 使用条件 |
|---|---|---|
| 多个候选在固定维度上一一对应 | 表格 | 单元格能用短句准确表达，读者需要逐列核对 |
| 两三个概念的局部差异或例外 | 连续段落 | 差异需要解释条件、原因或反例 |
| 至少三个步骤、分支、循环或先后依赖 | 流程图 | 只看文字容易走错路径或漏掉停止条件 |
| 三个以上方法共享同一输入但导向不同目标 | 概念定位图 | 图能显示分流关系，且不承载完整假设清单 |
| 数值、分布、效应、不确定性或模型诊断 | 真实统计图 | 由文章代码和真实对象生成，使用 `publication-figures` |
| 软件界面、命令、文档或渲染结果 | 真实截图 | 实际运行或渲染后获取，不用生成式图片伪造 |

表格和示意图可以互补，但不能逐字重复。表格承载精确条件，示意图只保留理解分流关系所需的最小标签；完整定义、限制和例外留在正文。

## 3. 图前合同

每个候选图位先写一句“删除这张图会失去什么理解”。答案若只是“页面不够丰富”或表格已经完整表达，则不生成。

确认需要图件后：

1. 在图前提出读图问题，让读者知道要观察什么关系；
2. 按证据属性路由：概念、流程、机制和框架使用 `research-visuals`，统计结果使用 `publication-figures`，真实界面使用截图；
3. 概念图的节点、箭头、方向和图内术语逐项回到正文、官方资料或方法来源核验；
4. 图中只保留删除后会造成关系误读的短标签，不把公式、长段落、完整比较表或未经核验的数值烧录进图片；
5. 图后解释主要关系、适用边界以及图中为了清楚而省略的内容；
6. 提供准确替代文本，描述结构、方向和关键分支，不写“下图展示”。

生成图必须完成查看、逐字逐边核验、必要修正、嵌入和最终网页复核。图中文字或关系无法可靠生成时，保留正确的表格与正文，不用错误示意图换取“图文并茂”。

## 4. 栏目迁移检查

- 统计方法：区分研究问题、estimand、效应尺度、相关性处理、缺失机制和诊断。
- R 包：区分任务边界、底层方法、安装来源、输入输出对象、默认值和下游兼容性。
- 可视化：区分图回答的问题、统计变换、数据形态、误读风险和导出载体。
- 实用操作：区分稳定/实验功能、平台或 shell、输入产物、权限和成功状态。
- 机器学习与 AI：区分预测与因果、开发/内部验证/外部验证/部署、产品表面和 API。
- 入门与专题：区分相似对象或语法，以及同名方法跨领域迁移时的构念、尺度和假设。
