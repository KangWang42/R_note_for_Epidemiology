EpiAgentKit：Claude Code 与 Codex 的流行病学和生物统计科研工作流

EpiAgentKit
科研 Skills
AI 工具
全面介绍 EpiAgentKit 的双平台架构、20 个科研 Skills、完整研究工作流、安装同步方式、确定性检查和安全边界。
发布于

2026年7月23日

EpiAgentKit 是本站重点维护的科研 Skills 库。它面向流行病学、卫生统计、临床研究和统计咨询，把项目规则、专业技能、文件工具、确定性检查和双平台配置管理组织成一套可执行工作流。研究者可以在 Claude Code 或 OpenAI Codex 中使用同一套规范，从研究问题与证据核验开始，继续完成 R 分析、统计图、论文、报告、汇报、咨询交付和项目审查。

重要本专题的阅读入口

本文负责解释 EpiAgentKit 是什么、整套系统如何协作以及怎样安装使用。20 个 Skills 完整目录集中列出全部技能；每个 skill 另有独立详解文章，说明触发条件、内部组成、执行流程、典型产物和能力边界。

核心定位

EpiAgentKit 不是新的统计软件，也不是一组需要反复复制的提示词。它是一套面向科研 Agent 的行为系统，主要解决四类问题：研究口径容易被模型猜测，分析代码写完却没有实跑，结果数字在论文和表图之间发生漂移，以及项目交付缺少可复现和可审查的证据链。

它采用按任务加载的 Agent Skills 机制。全局规则只保留每个会话都必须遵守的红线和路由，具体分析、写作、视觉、文件处理与审查步骤放在对应 skill 中，需要时才加载。这样既能保持专业约束，又不会把全部规范塞入每次对话。

研究问题 EpiAgentKit 的处理方式
分组、终点、纳排或主分析存在多种合理定义 停止猜测，先由研究者确认口径
原始数据可能被误改 规则与 hook 共同保护 01_data/rawdata/ 及项目声明的其他原始数据根
代码写了但没有运行 分析流程要求写入脚本、实际执行、扫描完整输出并核对结果
结果改了，论文数字没有同步 正式项目使用 results.yaml 保存机器可读结果，再派生报告、论文和 PPT 所需数字
图表能看但不符合最终载体 统计图与非统计视觉分流，按物理尺寸、字体、来源和载体分别验证
AI 文本改变事实或夸大论断 写作前锁定数字、引文、表图和论断方向，按研究设计校准措辞
咨询结果难以交接复现 从已验证主流程派生自包含交付包，并在隔离环境中复现
项目看似完成但内部不一致 六层项目审查与确定性预检共同阻止带 ERROR 的项目签发

双平台架构

EpiAgentKit 以同一个 GitHub 仓库作为 Claude Code 与 Codex 的配置源。仓库内容分为四层，各层承担不同职责。

层级 主要内容 作用
全局规则 CLAUDE.md、同步生成的 AGENTS.md 保存硬红线、最短路由、结果单源和完成条件
领域 Skills skills/*/SKILL.md、references/、scripts/、assets/ 按需加载专业工作流、长规范、确定性脚本和模板资产
Hooks hooks/ 在文件编辑或命令执行前后保护原始数据、检查 R 语法和提示结果格式问题
配置管理器 scripts/epiagentkit.py 完成安装、同步、冲突清理、双端验收和项目预检

Claude Code 与 Codex 不需要维护两套不同技能。安装器会根据平台真实目录进行映射，Codex 的自定义 skills 默认安装到 ~/.agents/skills/，Claude Code 使用自己的 skills 目录。doctor 负责核对安装清单、规则、skills 和 hooks 是否一致。

两种任务模式

EpiAgentKit 区分轻量任务与正式项目。这个边界决定是否需要完整目录、方案、结果单源和审查账本。

模式 适用情况 系统行为
轻量任务 简单作业、单次处理、快速核验或只需少量输出 只加载必要 skill，保持输入只读，集中输出并执行与风险相称的验证
正式项目 用户明确初始化项目、投稿、咨询交付，或工作区已有标准研究骨架 使用方案、统计分析计划、结果单源、日志、registry、备份和最终审查流程

触发某个专业 skill 不会自动把轻量任务升级为正式项目。例如，快速核验一个 DOI 可以只使用 evidence-research，不需要创建七层目录；只有研究治理和文件布局确实需要时，才使用 project-init。

完整研究工作流

一条典型主线由多个 skills 接力完成，而不是由单个技能包办所有工作。

  1. 问题与口径确认。 biostat-principles 先锁定分组、终点、纳排、分析集和主分析方法。存在多种合理口径时，由研究者决定。
  2. 证据核验。 evidence-research 核验方法依据、量表、结局定义或真实引文，并区分快速核验与正式证据综述。
  3. 项目初始化。 project-init 在明确需要正式项目时创建研究或咨询骨架，建立 PROTOCOL.md、SAP.md、结果单源和追溯文件。
  4. 统计分析。 r-biostats 编写并实跑 R 脚本，核对样本量、异常值、warning、结果范围和输出文件。
  5. 统计图制作。 publication-figures 根据真实数据关系选择图型，按最终宽高、字体、配色和导出格式完成检查。
  6. 论文、报告和汇报。 academic-publishing、report-writing 或 sysu-ppt 分别负责对应内容主流程，文件 skills 只在需要真实文件时加入。
  7. 学术审校。 academic-humanizer 锁定不可变事实，清理模板化表达并把论断强度校准到研究设计允许的范围。
  8. 咨询交付。 consulting-delivery 从已验证主流程派生外发包，禁止只改分享包而不回写主流程。
  9. 项目签发。 epi-project-audit 联合确定性检查逐层收集证据；ERROR 阻止签发，WARN 必须解释。

Skills 的组合原则

Skills 按“内容主流程、视觉或文件操作、终审”的顺序组合。论文从零生成使用 biostat-principles → academic-publishing → academic-humanizer，需要 Word 时再加入 docx；统计分析使用 biostat-principles → r-biostats，实际绘制结果图时加入 publication-figures；学术汇报使用 sysu-ppt，实际操作演示文件时加入 pptx。

统计图与非统计视觉严格分流。包含坐标、比例或真实数据映射的结果图使用 publication-figures；流程图、框架图、机制图、技术路线和图形摘要使用 research-visuals。svg-diagrams 是明确矢量需求或既定回退条件下的工具，不替代统计图工作流。

标准项目结构

正式研究项目使用稳定语义目录，把输入、代码、最终表图、中间结果、论文和备份分开。

01_data/rawdata/   只读原始数据
02_code/           编号分析脚本、config、conventions 与 registry
03_tables/         最终表格与附表
04_figures/        最终图件与附图
05_reports/        从主流程派生的报告或咨询交付包
06_results/        清洗后数据、模型对象和其他中间结果
07_paper/          论文部件、results.yaml 与人读结果摘要
09_backup/         旧版、一次性脚本和隔离探索

项目根还会保存研究方案、统计分析计划、方法决策、操作记录和待补事项。关键数字以 07_paper/results.yaml 为机器单源，0_result_summaries.md 只是便于阅读的派生版本。

安装与同步

基础安装需要 Python 3.10 或更高版本。R 只在执行 R 分析、统计出图或 R 驱动的 PPT 工作流时需要。EpiAgentKit 不负责安装或升级 R、Python、Node、Java、LibreOffice、TeX、Git 或依赖包；它只复制规则、skills、hooks 并执行安装检查。

git clone https://github.com/KangWang42/EpiAgentKit.git
cd EpiAgentKit
python scripts/epiagentkit.py install

没有 Git 时可以下载并解压源码，再运行同一安装命令。安装器支持 Claude Code、Codex 或双平台，结束时默认运行 doctor。已有个人配置会保留，只有 EpiAgentKit 受管文件和 hooks 会被更新。

常用安装方式

# Claude Code 与 Codex 完整安装
python scripts/epiagentkit.py install --target all --preset full --yes

# 统计分析组合
python scripts/epiagentkit.py install --target all --preset analysis --yes

# 论文、报告与证据组合
python scripts/epiagentkit.py install --target all --preset writing --yes

# PPT 与科研视觉组合
python scripts/epiagentkit.py install --target all --preset ppt --yes

# 自选 skills，并自动补齐依赖
python scripts/epiagentkit.py install --target all --preset custom \
  --skills sysu-ppt,report-writing --with-rules --yes

# 只演练，不修改用户目录
python scripts/epiagentkit.py install --target all --preset full --yes --dry-run

日常维护命令

# 查看可分发 skills 与预设
python scripts/epiagentkit.py list

# 从仓库同步已安装内容
python scripts/epiagentkit.py sync --target all

# 验证双平台安装一致性
python scripts/epiagentkit.py doctor --target all

# 对正式研究项目执行确定性预检
python scripts/epiagentkit.py check-project <项目根>

Hooks 与确定性检查

Skills 适合表达需要判断的专业流程，hooks 和脚本负责重复且需要确定性的检查。当前仓库包括以下主要能力。

检查 作用
原始数据路径保护 在可确定解析的编辑请求写入原始数据根之前阻断操作
R 语法检查 编辑 .R 文件后调用 Rscript 做 parse 检查
文本痕迹检查 扫描正式文本中的生成过程痕迹、禁止字符和明确 emoji
图件事件提醒 检测 04_figures/ 的新图或改图，要求按图件清单进行实际视觉核验
结果格式提醒 检测 06_results/ 新增 .rds，提示表格化数据应保存为 .xlsx
项目预检 检查目录、命名、日志、敏感信息风险、结果来源和当前版唯一性

Hook 只能覆盖可确定识别的机械边界，不能替代研究判断、文件权限和最终项目审查。例如，原始数据保护 hook 不会尝试理解任意 shell 或 Python 代码，因此仍需遵守原始数据只读规则并执行签发前检查。

安全边界

在授权范围内运行代码、生成成果、整理非原始文件并审查 修改原始数据，或在数据异常未闭环时擅自填补、排除并继续计算

典型使用场景

从队列数据到论文

研究者先确认暴露、结局、纳排和协变量，再由 project-init 建立正式项目。r-biostats 完成清洗、基线描述和 Cox 回归，publication-figures 输出森林图与生存曲线，结果数字进入 results.yaml。academic-publishing 依次生成方法、结果、引言、讨论与摘要，academic-humanizer 做证据约束终审，最终由 epi-project-audit 检查代码、数字、表图和正文一致性。

快速核验方法依据

如果只需验证一条 DOI、指南或统计方法依据，直接使用 evidence-research 的 rapid verification 模式即可。该任务保持轻量，不创建项目目录和账本；只有需要可复核检索协议、纳排记录和证据矩阵时，才进入 formal evidence review。

统计咨询交付

分析主流程完成并验证后，consulting-delivery 在 05_reports/ 生成自包含交付目录，整理运行入口、说明、表格和图件，并在新的 R 会话或用户已准备的 Python 隔离环境中复现。分享包是主流程派生物，发现错误必须先回主流程修复，再重新生成交付包。

组会、开题与答辩

sysu-ppt 根据体裁、汇报时长、内容关系和证据量设计逐页结构，复用中山大学模板并通过 officer R 包生成演示文件。统计图来自 publication-figures，非统计配图来自 research-visuals，最终文件由 pptx 执行内容和视觉质量检查。

适用对象

EpiAgentKit 适合需要持续处理流行病学、卫生统计、真实世界数据、临床研究、学位论文或统计咨询的研究者和团队。它尤其适用于一个人需要从原始数据一直做到表图、论文和交付的场景，也适合课题组统一项目结构、审查标准和交接方式。

如果任务只是临时计算一个小结果，完整项目结构可能过重。EpiAgentKit 因此保留轻量任务模式，只在用户明确初始化、投稿、交付或既有正式项目中启用完整项目规范。

常见问题

必须同时安装 Claude Code 和 Codex 吗？

不需要。安装器可选择 claude、codex 或 all。选择双平台的意义是让两个 Agent 共用同一规则与 skills，而不是要求同时使用。

必须使用 R 吗？

统计分析主技能 r-biostats 面向 R；咨询交付可以处理已完成的 R 或 Python 分析，文件处理和项目维护也不依赖 R。EpiAgentKit 不会为任务自动创建或升级运行环境。

每次都要记住 skill 名称吗？

不需要。自然语言任务会根据 description 自动路由，也可以在 Claude Code 中使用 /skill-name，或在 Codex 中使用 $skill-name 显式调用。

它会自动提交或推送 Git 吗？

在 Git 可用且当前目录已经是仓库时，明确修改请求完成并验证后可以按项目规则自动提交。只有用户当轮明确要求 push 时才会推送，不会强制推送或改写远端历史。

如何确认本机安装的是最新仓库内容？

在本地仓库更新源码后运行 sync --target all，再运行 doctor --target all。list 可以显示当前可分发 skills 与预设组合。
