# R 包比较框架

包状态、速度和功能会变化，比较前应核对当前官方资料并记录版本。不要维护未经验证的“活跃/过时”静态名单。

## 比较维度

| 维度 | 需要核对 |
|---|---|
| 任务与 estimand | 两个包是否真的解决同一问题，默认目标量是否相同 |
| 输入输出 | 数据格式、缺失处理、因子编码、返回对象和下游兼容性 |
| 算法 | 底层实现、近似、默认参数、随机性和数值稳定性 |
| 诊断 | 是否暴露残差、收敛、权重、校准或错误状态 |
| 依赖与平台 | R 版本、编译需求、系统库、许可证和安装渠道 |
| 维护 | 当前版本、发布日期、变更日志、问题跟踪和归档状态 |
| 性能 | 同一数据、硬件、版本、线程和正确性检查下的基准 |
| 教学成本 | 语法、错误信息、文档和最小可运行示例 |

## 比较规则

- 先验证输出在统计含义上可比，再比较速度。
- 不以 GitHub star、下载量或函数数量代表质量。
- 不把“接口简洁”写成“方法更准确”。
- 公平基准需预热、重复、报告数据规模和内存，并验证结果一致。
- 包有同名函数时使用 `package::function()`，不要依赖加载顺序。
